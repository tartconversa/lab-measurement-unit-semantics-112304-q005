# 科研测量语义化数据湖——系统说明

本系统面向多设备、多实验方案、多分析工具产生的异构测量结果，提供三类可交付能力：

1. **可配置异构测量装载**：显式列映射，宽表/长表、CSV/JSONL 均可接入，原始值不被改写；
2. **语义校验**：以量纲、测量性质（绝对量/差值/设定值）、基准条件为核心，防止“列名相同即合并”；
3. **版本化共享数据集生成**：注册表与数据集均带版次，标准修订后可重算并逐行追溯转换、排除、保留原单位的历史。

全部能力仅依赖 Python 3.11+ 标准库，持久化使用内置 SQLite，无外部服务。

## 1. 角色与职责划分

| 角色 | 系统中的落点 |
| --- | --- |
| 领域数据管理员 | 维护 `config/registry_v*.json`：单位量纲、换算公式与版次、指标定义、指标×基准条件规则及审批状态 |
| 数据工程人员 | 维护来源配置 `config/sources/source_config.json`，执行装载与标准化；原始层/标准化层与转换版次由系统固化 |
| 研究分析人员 | 维护合并策略 `config/policies/*.json`，声明**允许合并**的语义键集合，并裁决同名列冲突告警 |

三类配置相互独立，任何一方都无法绕过另两方改变科学量的语义。

## 2. 分层模型

```
设备文件（CSV/JSONL）
   │  可配置装载（loader.py，显式列映射，不推断语义）
   ▼
raw_records 原始层（不可变，INSERT OR IGNORE 去重，保留原始数值/单位/样品/设备/方案/环境条件）
   │  按注册表版次评估（validation.py）
   ▼
standardized_rows 标准化层（按 registry_version 分区，重跑幂等，旧版次永久保留）
   │  按研究分析人员合并策略发布（dataset_engine.py）
   ▼
datasets / dataset_rows 共享层（数据集版本递增；shared 与 restricted 两个层级）
```

## 3. 语义校验规则与处置

| 规则号 | 含义 | 默认级别 | 处置 |
| --- | --- | --- | --- |
| U001 | 单位/指标未在注册表登记 | error | 排除 |
| D001 | 单位量纲与指标量纲不一致 | error | 排除 |
| M001 | 记录测量性质与单位登记性质冲突 | error | 排除 |
| M002 | 指标不允许该测量性质（如设定值并入被测温度） | error | 排除 |
| B001 | 指标×基准条件规则未登记 | warning | 受限保留 |
| B002 | 基准必需的环境条件字段缺失 | warning | 受限保留 |
| R001 | 基准规则处于 draft/retired 未批准状态 | warning | 受限保留 |
| C001 | 模板换算所需参数缺失（防御路径） | warning | 受限保留 |
| N001 | 标准化值超出指标合理区间 | info | 不阻断 |

严重级别可在 `config/validation_rules.json` 中覆盖（只能调到系统已知的规则号）。

**处置三态**：

* `converted`：校验全通过并完成版本化换算，进入 `shared` 共享数据集；
* `retained_original`：存在 warning，**保留原单位、不补造任何精确换算值**，只进入 `restricted` 受限数据集，清单逐行记录原因；
* `excluded`：存在 error，不进入任何数据集，仅在清单审计段留痕。

## 4. “格式可转换 ≠ 语义相同”的关键设计

### 4.1 测量性质三分

即使量纲同为 temperature，系统也强制区分：

* `absolute` 绝对温度：允许仿射换算（摄氏度 `K = degC + 273.15`）；
* `difference` 温差：注册表加载即拒绝带偏移的单位定义（offset 必须为 0），1.5 ℃ 温差只能得到 1.5 K；
* `setpoint` 设定值：设备控制目标而非被测物理量，使用独立标准单位 `K_setpoint`，语义键与被测温度天然不同，无法误并。

### 4.2 浓度归一基准隔离

干质量归一（`mass-fraction`，mg/kg）与湿体积归一（`mass-concentration`，mg/L）量纲不同、标准单位不同，注册表层面即不可互算。气体 mg/m³ → mg/L 使用带基准条件的模板换算（摩尔体积），基准温压字段缺失时走 B002 受限保留，而不是猜测一个摩尔体积。

### 4.3 语义合并键与同名列冲突检测

合并键为 `指标|基准条件|测量性质|可比组`，**列名完全不参与键计算**。发布引擎另做反向检查：若同一列名（如 `temperature`）在不同来源承载了不同语义键，清单输出 `column_name_collision` 告警，由研究分析人员裁决，系统不自动合并。

## 5. 标准修订与版本化流程

1. 复制注册表为新版本号（如 `REG-2026-02`），修订换算因子、`conversion_id`、`standard_version`、规则审批状态；
2. 对同一批原始记录重新 `validate`，标准化层新增一个版次分区，旧分区不动；
3. 重新 `publish`，数据集版本号自动递增；
4. 用 `diff-registry` 对比两版：只有受影响的行（本合成场景为 3 行气体浓度）值与换算条目变化，其余行保持不变；
5. 任一历史行可用 `lineage` 查到原始值、两个注册表版次下的评估结果、以及进入过的全部数据集版本。

缺失基准条件的旧结果不会因新标准出现而被“补算”——它们在两个版次下均为 `retained_original`。

## 6. 命令行用法

```sh
export PYTHONPATH=src
python3 -m lab_measurement_unit_semantics.cli --json init     --db lake.db
python3 -m lab_measurement_unit_semantics.cli --json ingest   --db lake.db --config config/sources/source_config.json
python3 -m lab_measurement_unit_semantics.cli --json validate --db lake.db --registry config/registry_v1.json --rules config/validation_rules.json
python3 -m lab_measurement_unit_semantics.cli --json policy   --db lake.db --policy config/policies/cross_lab_analyte.json
python3 -m lab_measurement_unit_semantics.cli --json publish  --db lake.db --dataset cross-lab-analyte \
       --policy POLICY-CROSS-LAB-ANALYTE --registry-version REG-2026-01 --tier both
python3 -m lab_measurement_unit_semantics.cli --json diff-registry --db lake.db --old-version REG-2026-01 --new-version REG-2026-02
python3 -m lab_measurement_unit_semantics.cli --json lineage  --db lake.db --record-id 'SRC-LAB-B:lab_b_sensor.csv:r1:gas_conc'
python3 -m lab_measurement_unit_semantics.cli --json versions --db lake.db --dataset cross-lab-analyte
```

去掉 `--json` 可获得中文文本渲染输出。也可直接作为库使用，入口类：
`Registry`、`load_all`、`evaluate`/`ValidationConfig`、`Repository`、`DatasetEngine`。

## 7. 合成测试数据覆盖的场景

| 来源 | 场景 |
| --- | --- |
| LAB-A 温度计 | 摄氏绝对温度仿射换算；缺气压行受限保留；缺失值跳过 |
| LAB-A 移液器 | 微升→毫升线性换算；校准基准 |
| LAB-B 传感器 | 温差无偏移换算；气体模板换算；缺基准压力行不补造 |
| LAB-C 质谱 | μg/kg→mg/kg；干质量基准；缺烘干湿度行受限 |
| LAB-C 腔体控制器 | 同名列 `temperature` 实为设定值，独立语义键 |
| LAB-99 旧设备（JSONL） | 未登记厂商单位→排除；未知基准/草案规则→受限；无精确换算补造 |

测试：`python3 -m unittest discover -s tests -v`（共 36 个用例，含基线资料契约测试）。
